# 公开来源与审查完整性元数据

公开职业事实与来源说明应由读者通过真实公开 URL、来源内的章节、题名、表格或实际页码追溯。内部工具会话编号、工具输出行号、本机文件路径，以及没有公开目标的研究或审稿文件名，不是读者可复核的证据链接，不得放入公开数据或导出。

## 保留的内容

- 人物、事件、来源与批次的稳定 ID，以及来源闭合和三态未知判定。
- 真实公开 URL、实际获取时间、访问失败与冲突说明、原文可定位的章节、题名和页码。
- 确实存在于本仓库的公开文件引用，以及导出工作表和单元格范围。
- 用于版本、审查或身份匹配的完整性摘要，且不得改变其原有作用域。

摘要不是链接，也不能替代直接来源。网页/PDF原始字节、摘录、结构化最小事实、工具响应、研究包、独立审稿和测试 fixture 的摘要各自只描述其对应对象，不可互换。原来未说明摘要范围的记录不能仅凭字段名称被升级为“原始网页/PDF已独立核验”。

## 元数据清理与历史契约

本次维护仅清理来源定位与审查元数据，不新增人物，不改变学位授予三态、学历筛选、任职、师承、论文归属、采样顺序、待完善或暂缓状态，也不刷新人物核验日期。

删除非公开定位后，包含这些定位的历史对象摘要会变化。历史公共视图采用明确版本与旧/新摘要映射，继续核对全部保留事实、来源、顺序、长度和未知字段边界。旧版本完整性指纹可保留作为历史标识，但不得声称当前公共视图能够重建已移出公开库的内部原值。

构建校验应拒绝新增的非公开定位，而不是在生成时悄悄删掉它们。真实人物 fixture 与公开进度文件遵守同一规则。用于验证拒绝行为的合成负例可以保留，但不能借负例例外保存真实内部定位。

## 本地检查

完整构建 `python scripts/build.py` 自动执行输入检查和最终公开树检查。也可单独执行 `python scripts/public_metadata.py --phase preflight` 或 `python scripts/public_metadata.py --phase final`。前者不检查旧站点副本，后者检查 JSON、文档、CSV 与 XLSX。`--data-only` 构建不重新生成或验收 XLSX，不能代替完整导出检查。新增公开根文件或目录必须明确纳入检查边界，不能被静默跳过。
