# 数据补全与跨环境接续

目标是逐步覆盖39所985高校，先完成哈尔滨工业大学一校三区。当前样板不是完成标准。公开资料范围、人事在职范围、人物详细资料范围必须分别记录。

## 持久化文件

- `research/coverage-work-queue.json`：组织入口与公开页面观察记录。来自采集的新观察必须审核，不能由页面“可读”自动推成组织归属或名录完整。
- `progress/work-queue.json`：经审核的执行检查点，遵循 `schema/work-queue.schema.json`。已纳入审核后的首批组织入口检查点。
- `data/atlas.json`：已核实的详细资料及字段级来源、未知与冲突。
- `data/rosters.json`：独立名录记录，不等同于个人档案或在职人员。

不得依赖聊天内容、本机缓存或未推送的文件继续工作。可复用事实、来源、分类/分页游标、阻碍与产物路径必须随批次提交到仓库。不要把凭据、访问令牌、内部任务/会话标识、私人笔记或受版权保护的长篇原文写入队列。

## 任务阶段

1. `organization_validation`：核对学校/校区/组织类型和目录展示关系，区分明确来源与候选归属。分支校区不能按总部所在地推断。
2. `roster_enumeration`：遍历明确列出的系所、职称分类和分页；记录来源范围、可见条目数、缺页和同名/同链接冲突。完成仅指指定来源范围已遍历。
3. `profile_research`：逐人核对身份，再记录教育、任职、导师、委员会与论文。已查却未公开的字段明确标缺项；不能把未查与未披露混为一谈。
4. `source_review`：独立复核字段与关系证据，保留冲突，不根据共著或页面存在推断导师/在职。
5. `export`：规范数据、静态快照与Excel/CSV一致；检查计数、来源、筛选与缺项口径。

父子单位存在重叠时不得加总人数。组织数、名录记录数、去重身份数、详细档案数、已核实在职人数分别统计。没有经核实分母时不显示“全校完成百分比”。现有78节点仅是已整理组织索引，不能当作完整组织树或78个学院。

## 状态定义

| 状态 | 意义 |
| --- | --- |
| pending | 尚未处理或已明确退回待处理 |
| in_progress | 单一主控正在执行，记录开始时间与基准commit |
| partial | 有可保存进展，但本任务指定范围尚未走完 |
| blocked | 指定动作受阻，必须写明原因及可接受的重试条件 |
| done | 该任务明确范围已走完、产物存在、审核通过；不代表个人资料齐全或全校完成 |

`done`必须有审核通过、证据URL、核对时间、产物路径和未决项列表；不能用“页面打开成功”作为名录枚举或人物核验的完成条件。未披露与冲突是可记录的结果，但不能伪造完整事实。当前schema固定 `registry_complete=false` / `university_complete=false`，待真正全校验收时再通过明确审核扩展完整性声明。

## 恢复流程

1. 读取远端默认分支HEAD、队列、已提交数据与对应规范。核验 `base_commit` 和最近数据提交，不依赖本机副本。
2. 先查同一 `task_id` 是否完成或正在执行。不可重复开展正在运行的同一任务；接续前检查远端提交与原动作结果。
3. 由单一主控更新状态，记录执行时间和基准SHA。修改采用expectedSHA检查，不force覆盖并发改动；不引入分布式锁或租约系统。
4. 严格处理本任务来源范围；随时保存 `next_cursor`、下一步和可验证来源。遇访问拒绝停止对应动作，不换路绕过。
5. 每批将数据、来源、队列状态、派生快照/导出一起提交，保持小批次可审核。未通过复核的资料只能标待核，不提升为详细档案。
6. 更新分支后读回commit/tree与关键产物。`last_verified_commit`只写已实际核验的历史commit，不写当前提交尚不存在的自引用SHA。
7. 若HEAD变化，先读取差异并协调，禁止盲目重试或覆盖他人状态。结束时更新状态，并写明下一可做事项。

## 校验

安装开发依赖后运行：

```sh
python -m pip install -r requirements-dev.txt
python scripts/validate_queue.py progress/work-queue.json --check-artifacts
npm test
python -m unittest discover -s tests -v
```

合成测试只能证明约束有效，不能证明真实采集进度。真实队列必须另行检查来源范围与产物。

## 最小CI建议（尚未启用）

仅代码/数据校验，不部署：在push或pull_request触发，仓库内容权限只读，固定Node/Python版本，安装开发依赖，运行JS/Python测试和JSON Schema/队列检查。约束包括ID唯一、引用存在、来源必填、同名不自动合并、委员会不算导师、Excel/JSON记录一致。

CI不需要任何token、账号密码、部署密钥、Pages权限或对外写入；不在CI中访问教师网站或做大规模采集。依赖安装使用标准包源。上游Actions应固定完整commit SHA并经核验后再写workflow。当前未创建workflow，不声称远端CI已通过。
