# JSON 表示形式优化（人物事实不变）

基于已发布713份人物资料，紧凑序列化规范输入 data/atlas.json 与实际生成的 site/atlas.json，保留UTF-8原字符、全部字段、类型、对象键顺序、数组顺序及末尾单个换行。不改人物、组织、来源、学历、任职、关系、课程或作品，不压缩/删除证据字段；不是仅上传前临时修改文件。

普通构建不改规范输入；后续经审核的人物追加须继续使用同样紧凑规则。构建器仅修改site atlas写出表达式，拒绝NaN/Infinity，其他引擎、模型、页面及历史fixture/pins不变。data/rosters原始字节不改；所有院系与待核对Excel均须逐字节保持。

build_id原算法包含规范输入与构建器的原始字节，所以此格式改动必须产生新的派生build_id，并同时更新site atlas/rosters的该顶层字段。除此两项派生值外，所有解析后对象须严格等值且顺序相同，不保留旧build_id掩盖版本变化。

新增真实live格式、类型/顺序、Unicode/字符串空白及数值边界测试；既有历史序列化协议和字节pin不重签，live整文件引擎保护只精确允许这一行格式写出变化，不能把功能测试转到旧fixture。完整构建确定性、全套正常测试、独立差异/公开性及浏览器实际下载通过后才发布。
